# infra/

The AWS CDK stack for sPOKiy. One command builds the backend and frontend and deploys
everything; the site comes out at an HTTPS CloudFront URL with sign-up working.

```
infra/
  bin/spokiy.mjs          CDK app: one stack, SpokiyStack, region eu-central-1 by default
  lib/spokiy-stack.mjs    everything the stack creates, with the reasons in comments
  cdk.json                tells the CDK CLI how to run the app
```

## What it creates

| Resource | Details |
|---|---|
| **Cognito** user pool `spokiy-users` + app client `spokiy-web` | e-mail is the username; confirmation by e-mailed code; password 8+ characters, no other rules (matches the sign-up form); SRP auth; no client secret |
| **DynamoDB** ×3, on-demand | progress `userId`/`topicId` · requests `topic`/`userId` · feedback `userId`/`createdAt` |
| **Lambda** `ApiFunction` | Node 22, arm64, 512 MB, handler `lambda.handler`, the `backend/` folder as-is; read/write on the three tables and nothing else |
| **HTTP API** `spokiy-api` | one catch-all route to the Lambda; Express does the routing and CORS |
| **S3** + **CloudFront** | private bucket behind Origin Access Control; HTTPS only; unknown paths fall back to `index.html` for React Router; `config.json` never cached |

Lambda environment, set by the stack:

```
NODE_ENV=production        also what disables AUTH_BYPASS
COGNITO_USER_POOL_ID       COGNITO_CLIENT_ID
TABLE_PROGRESS             TABLE_REQUESTS            TABLE_FEEDBACK
CORS_ORIGINS               https://<cloudfront domain>,http://localhost:5173
```

**`config.json` is generated by the deploy.** The stack writes the real `apiUrl`, `region`,
`userPoolId` and `userPoolClientId` into the deployed site, replacing the localhost
placeholder from `frontend/public/`. There is no manual step after deploying.

**The Lambda is not bundled.** `backend/src/routes/topics.js` reads the quiz bank from disk
next to itself; a bundler would separate code from data. The backend folder is uploaded
with production `node_modules`, which `npm run deploy` installs first. `.env` is excluded.

## One-time setup

You need **Node.js 22+** and the **AWS CLI v2**.

```powershell
# Windows
winget install OpenJS.NodeJS.LTS
winget install Amazon.AWSCLI
# then open a new terminal so both are on PATH
```

```bash
# macOS
brew install node awscli
```

Sign the CLI in to the AWS account. With an IAM user's access key:

```bash
aws configure
#   AWS Access Key ID:      <key>
#   AWS Secret Access Key:  <secret>
#   Default region name:    eu-central-1
#   Default output format:  json

aws sts get-caller-identity      # should print the account id
```

(With IAM Identity Center instead: `aws configure sso`, then add `--profile <name>` to the
`cdk` commands below, or set `AWS_PROFILE`.)

Install the CDK and bootstrap the account. Bootstrapping creates the bucket CDK uploads
assets to; it is once per account and region.

```bash
cd infra
npm install
npx cdk bootstrap
```

## Deploy

```bash
cd infra
npm run deploy
```

That runs, in order:

1. `npm ci --omit=dev` in `backend/` — the Lambda's dependencies
2. `npm ci` and `npm run build` in `frontend/` — `frontend/dist`
3. `cdk deploy` — shows the IAM changes and asks `y/n` the first time

The first deploy takes about 5–10 minutes, most of it CloudFront. It ends with:

```
Outputs:
SpokiyStack.SiteUrl          = https://dxxxxxxxxxxxx.cloudfront.net    ← the site
SpokiyStack.ApiUrl           = https://xxxxxxxxxx.execute-api.eu-central-1.amazonaws.com
SpokiyStack.UserPoolId       = eu-central-1_XXXXXXXXX
SpokiyStack.UserPoolClientId = xxxxxxxxxxxxxxxxxxxxxxxxxx
SpokiyStack.TableProgress    = SpokiyStack-ProgressTable...
SpokiyStack.TableRequests    = SpokiyStack-RequestsTable...
SpokiyStack.TableFeedback    = SpokiyStack-FeedbackTable...
```

The same values are saved to `infra/cdk-outputs.json` (git-ignored).

**Check it works:**

```bash
curl <ApiUrl>/health       # {"ok":true,"authBypassed":false}
curl <ApiUrl>/topics       # the five topics
```

Then open the `SiteUrl`, create an account, confirm the e-mailed code, sign in, open a
lesson, vote on the Request page.

**Redeploying** after a code change is the same command. Only what changed is updated, and
the CloudFront cache is invalidated so the new site shows up within a minute or two.

`npm run diff` shows what a deploy would change without changing it.

## Running the frontend locally against the deployed API

Useful for teammates who want real sign-in and real tables while working on a page. Put
the outputs into `frontend/public/config.json` (do not commit it):

```json
{
  "apiUrl": "<ApiUrl>",
  "region": "eu-central-1",
  "userPoolId": "<UserPoolId>",
  "userPoolClientId": "<UserPoolClientId>"
}
```

`http://localhost:5173` is in the API's `CORS_ORIGINS`, so `npm run dev` just works.

Or run the backend locally against the real tables: put the `Table*` outputs into
`backend/.env` (`TABLE_PROGRESS=…` etc.). Your own AWS credentials are used for DynamoDB.

## Costs

For a class-sized audience this is within the AWS Free Tier or a few cents a month:
on-demand DynamoDB and Lambda bill per request, Cognito is free up to 10,000 monthly
users, CloudFront and S3 serve a ~1 MB site.

Cognito sends confirmation e-mails with its built-in sender, which is limited to
**50 e-mails a day**. Plenty for the live test; for a wider launch it would need SES.

## Tearing it down

```bash
cd infra
npm run destroy
```

The site bucket, the Lambda, the API and CloudFront are deleted. **The user pool and the
three tables are kept on purpose** — they hold the accounts, votes and feedback the
validation report is built from. Once that is done, delete them by hand in the AWS
console (Cognito → User pools, DynamoDB → Tables), or they stay at no cost while idle.

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| `This stack uses assets, so the toolkit stack must be deployed` | Run `npx cdk bootstrap` once. |
| `Unable to resolve AWS account to use` | The CLI is not signed in: `aws sts get-caller-identity` must work first. |
| Synth warns `frontend/dist is missing` or `backend/node_modules is missing` | You ran `cdk deploy` directly. Use `npm run deploy`, which builds first. |
| The site loads but says it cannot reach the API | Open `<SiteUrl>/config.json`: it must show the real `apiUrl`. If it shows `localhost`, the deploy did not finish — rerun it. |
| `GET /progress` returns 401 on the site | Signed-out user, or a stale session from before a redeploy. Sign out and back in. |
| `Internal error` from the API | Logs: `aws logs tail <ApiLogGroup output> --follow` |
| Confirmation e-mail never arrives | Check spam; then the 50-a-day limit above. A user can be confirmed by hand in the Cognito console. |
| A deep link like `/topics/pipelining` gives 403 | The error responses are missing — check the distribution was deployed by this stack. |
